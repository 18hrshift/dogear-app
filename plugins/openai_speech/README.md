# Speech service voices for Dogear

This adds voices from speech services to [Dogear](https://github.com/18hrshift/dogear-app):
any service or server that takes speech requests the way OpenAI's speech API does
(`POST <base_url>/audio/speech`). That includes OpenAI itself, other services that copy
its API, and servers you run on your own computer.

**Read this first.** Dogear's own voice, Kokoro, runs on your computer, and your books
never leave it. A service on another computer is different: Dogear sends it the book's
text, one sentence at a time, and the service sends back the audio. That service then has
the text, its own terms and privacy policy apply, and it usually charges for it. So Dogear
uses such a voice only if you allow it, and says where the text is going before it sends
any. A server on your own computer keeps the text there, and needs no permission.

## Install it

The Dogear installers and the Docker image can't take plugins yet. This is for Dogear
installed with Python and [uv](https://docs.astral.sh/uv/), as Dogear's README describes.
Install Dogear and this plugin together with one command:

```bash
uv tool install git+https://github.com/18hrshift/dogear-app \
  --with "dogear-openai-speech @ git+https://github.com/18hrshift/dogear-app#subdirectory=plugins/openai_speech"
```

If Dogear is installed already, the same command installs it again with the plugin. From
a copy of Dogear's repository, run `uv run --with-editable ./plugins/openai_speech dogear
voices` instead, or install it into Dogear's environment with `uv pip install -e
plugins/openai_speech`. Don't use `pip install dogear`: that name on PyPI belongs to a
different project.

Then `dogear voices` lists the service's voices after Kokoro's, each marked with the
computer it sends the book's text to, such as "(sends the book's text to api.openai.com)".

## Use OpenAI

Out of the box the plugin is set up for OpenAI, with its model `gpt-4o-mini-tts` and its
13 voices, `marin` and `cedar` first (OpenAI says they sound best).

1. Get a key from OpenAI, and put it in the environment variable `OPENAI_API_KEY`. The key
   never goes in a settings file. On Linux and macOS, for one terminal window:
   `export OPENAI_API_KEY=your-key`. On Windows, in PowerShell: `$env:OPENAI_API_KEY =
   "your-key"`.
2. Make a book with one of its voices, and allow it for this run:

```bash
dogear make mybook.epub --voice marin --allow-cloud
dogear say "Utterson met Lanyon." -o test.wav --voice marin --allow-cloud
```

Without `--allow-cloud`, Dogear stops before it reads the book, says which computer the
voice would send the text to, and sends nothing. With it, Dogear first says, in plain
sentences, that the text is going to api.openai.com and that OpenAI's terms apply. To allow
cloud voices every time, and to have the web page offer them, put this in your settings
file:

```toml
[voice]
allow_cloud = true
engine = "openai_speech"  # to use one every time
voice = "marin"
```

What it costs, as OpenAI's [price list](https://developers.openai.com/api/docs/pricing)
gave it on 2026-10-30: `gpt-4o-mini-tts` is $0.60 per million tokens of text and $12 per
million tokens of audio, which OpenAI estimates at about 1.5 cents a minute of audio. A
100,000-word novel is about 11 hours, so roughly $10. `tts-1` is $15 per million characters
and `tts-1-hd` $30, so the same novel is about $8 or $16. Slower speech costs more with
`gpt-4o-mini-tts`. Prices change: check the service's own list. Dogear keeps every sentence
it has been sent back, so making the same book again, or carrying on after stopping, is
paid for only once.

OpenAI says its speech models, `gpt-4o-mini-tts`, `tts-1`, and `tts-1-hd`, shut down on
January 6, 2027, and that what replaces them works through a different API. After that
date this plugin needs another service. OpenAI also asks that listeners are told the voice
is generated by AI.

## Use a server on your own computer instead

A speech server running on your computer keeps the book's text there: no permission is
needed, and Dogear doesn't warn. Point `base_url` at it, with its model and voices. For
example, [Kokoro-FastAPI](https://github.com/remsky/Kokoro-FastAPI) (Docker) listens on
port 8880:

```toml
[openai_speech]
base_url = "http://localhost:8880/v1"
model = "kokoro"
voices = ["af_heart", "bf_emma"]
requests_per_minute = 0  # no limit: it's your own server
```

[Speaches](https://speaches.ai/usage/text-to-speech/) (port 8000, model
`speaches-ai/Kokoro-82M-v1.0-ONNX`) and [LocalAI](https://localai.io/features/text-to-audio/)
answer the same requests. Dogear treats only `localhost`, `127.0.0.1` (and the rest of
`127.x.x.x`), and `[::1]` as this computer. Any other address, a computer on your own
network included, is another computer, so Dogear asks first. If a voice name is also one of
Kokoro's built-in voices, choose it as `openai_speech:af_heart`.

Dogear's own Kokoro voice needs no server at all, so a local server is mostly useful for a
model Dogear doesn't have.

## Other services

Set `base_url`, `model`, `voices`, and `api_key_env` to what the service gives, and check
two more settings against its documentation:

- `response_format`: `"wav"` (the default; Dogear reads its sample rate from it), or `"pcm"`
  for a service that sends only raw 16-bit samples.
- `sample_rate`: 24000 for OpenAI and Kokoro servers, 22050 for most Piper voices. With WAV,
  Dogear stops and says which rate to set if it doesn't match.
- `max_input_chars`: the most characters the service takes at once. Dogear sends sentences
  of up to 400 characters (`max_sentence_chars` under `[speech]`) and stops before sending
  any if that is more than the service takes. Groq's Orpheus voices, for example, take 200.

## Every setting

These go in a `[openai_speech]` table in your settings file. The defaults, with what each
does, are in [`src/dogear_openai_speech/settings.toml`](src/dogear_openai_speech/settings.toml).

- `base_url`, `model`, `voices`: the service, its model, and the voices to offer, best first.
- `language`, `language_name`: what the voices speak, as a tag and in words (`en-US`,
  American English).
- `api_key_env`: the name of the environment variable that holds the key (`OPENAI_API_KEY`).
  A server on this computer usually needs no key; set it to `""` to send none anywhere.
  Dogear never sends a key over plain `http://` to another computer.
- `instructions`: how to speak, for a model that takes directions, such as
  `"Read calmly, like an audiobook narrator."`
- `response_format`, `sample_rate`, `max_input_chars`: above.
- `timeout_seconds` (60), `retries` (4), `retry_wait_seconds` (2): a request that fails in a
  way that may pass (asked to slow down, a server error, a lost connection) is tried again,
  waiting 2, 4, 8, then 16 seconds, or as long as the service asks, up to two minutes.
- `requests_per_minute` (50): at most this many requests a minute; 0 for no limit.
- `words_per_minute` (150): only for the disk-space estimate.

Dogear's `[voice] speed` is sent as the request's `speed`. Spellings in your pronunciation
files apply, because Dogear changes the text before sending it. Phoneme entries don't, and
`dogear words` doesn't apply: they are for Kokoro.

## What can go wrong

Dogear stops with a message that says what to do: a key turned down (401: check the key in
`OPENAI_API_KEY`), a key a request can't carry (one with a line break, a space, another
control character, or a character outside Latin-1, such as two keys pasted together or a
curly quote), asked to slow down even after trying again (429: lower
`requests_per_minute`, or wait), an account out of credit, a service error (5xx: try again
later), or audio that isn't what the settings say. The sentences spoken before the stop are
kept, so running the same command again carries on.

Known limits: a service may read some markup in the text its own way (Groq's Orpheus reads
`[cheerful]` as a direction, for example), and Dogear can't stop that. Redirects aren't
followed, so the text goes only to the address in `base_url`.

## Working on it

```bash
uv run --frozen --with-editable ./plugins/openai_speech pytest plugins/openai_speech/tests
```

Run that from Dogear's repository folder. The tests use a fake speech service on this
computer (`tests/fake_service.py`), so they need no network and no key. To try the plugin
by hand with real audio, make a recording with `dogear say "Hello there." -o speech.wav`,
then serve it with `python plugins/openai_speech/tests/fake_service.py --audio speech.wav`
and set `base_url = "http://127.0.0.1:8899/v1"`.
